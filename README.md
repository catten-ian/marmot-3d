# 土拨鼠大作战 3D · 第一人称

基于 2D 俯视版《土拨鼠大作战·闯关爆发版》重写的 three.js 第一人称网页游戏。

## 两个版本

| 版本 | 地址 | 说明 |
|---|---|---|
| 正式版 | `index.html` | 默认，保持原有浆果采食与数值手感 |
| **DEV 版** | `index.html?version=dev` | **A Verdant Trail 环境 + 旱獭真实生态学改写**，实验分支 |

两者共存、互不影响，页面底部有版本角标标识。

### DEV 版改了什么（依据旱獭生态资料）

旱獭是**典型草食动物**，耐饥渴，因此 dev 版做了三处改写：

1. **食性：采食对象改为草本植物**
   旱獭主食为沙草料、禾本科叶茎、豆科花，不是浆果。
   草本植物按外形分为三类（丛生细叶 / 豆科三叶小花 / 穗状种子），玩家能直接辨认。
   灌木丛在 dev 版整体隐藏，避免误导。

2. **耐饥渴：做成实际手感**
   移动消耗 ×0.62、挥爪消耗 ×0.7、静止恢复 ×1.9、洞内恢复 ×1.35；
   储备见底的惩罚从「移速 ×0.62 / 伤害 ×0.8」放宽到「×0.9 / ×0.94」，
   见底判定线从 8 降到 4 —— 能撑过长时间不进食，符合耐饥渴的生物学特征。

3. **季节性与食性偏好**
   五关依次映射真实季节：

   | 关 | 季节 | 代表植物 |
   |---|---|---|
   | 1 | 早春 | 冷蒿嫩芽、苜蓿新叶、红三叶草 |
   | 2 | 晚春 | 沙草、禾本科嫩叶、苜蓿花、野豌豆 |
   | 3 | 初夏 | 羊草、冰草、紫花苜蓿、谷子 |
   | 4 | 夏末 | 寸草、蒿属草本、马齿苋、稗草 |
   | 5 | **冬眠前** | **亚麻、胡麻、玉米粒、向日葵籽** |

   - 「冬眠前与早春进食最强烈」→ 这两关的食物提示会说明当前正为储备能量
   - 「偏好含水量高的多汁饲料」→ 多汁植物额外 +8 储备
   - 「偏好富含脂肪的植物，尤其含亚油酸」→ 泛淡金环的植物额外 +12 储备，仅冬眠前关大量出现

> 能量换算系数仍是**玩法设计**，不代表实测营养摄入量或能量代谢率。
> 资料提到旱獭「有时也会吃些动物」「饲养条件下更杂食」，说明食性有弹性，
> 但游戏不据此设计捕食行为。

### 生态边界与游戏尺度

| 对象 | 游戏模型高度/尺度 | 现实参照 | 说明 |
|---|---:|---:|---|
| 喜马拉雅旱獭 | 视高 0.46m，模型约 0.8m | 体长 0.50–0.65m、肩高约 0.30m | 第一人称视高用于玩法与观察，不是肩高 |
| 藏狐 | 模型目标高度 0.92m | 肩高约 0.38–0.45m | 模型为提高低机位下的可读性而放大，不是实物比例 |

单只旱獭在游戏中能够驱退藏狐，是策略游戏的玩法抽象；现实中旱獭主要依靠群体警戒、报警和躲入洞穴避险，不应据此推断单只旱獭能够战胜藏狐。冬眠前关卡里的亚麻、胡麻、向日葵籽和玉米代表近人环境中的栽培食物补充，不是野生草原植被清单。

### 一个设定上的收获

草食设定反而让「驱赶而非击杀」更站得住：**旱獭面对威胁主要靠警告与驱离应对**，
不是捕食。这与游戏里「把藏狐赶到别处、别进我的洞口和采食区」的行为一致。


## 运行

**Windows 用户：双击 `start-server.bat` 即可。**
脚本会自动定位 Node、启动服务器并打开浏览器。

想换端口：命令行执行 `start-server.bat 9000`

手动方式：

```bash
# 方式一：项目自带服务器（零依赖，推荐）
node tools/serve.cjs 8200

# 方式二：Python
python -m http.server 8200
```

然后浏览器打开 **http://127.0.0.1:8200/**

需要通过 HTTP 访问（使用了 ES module），直接双击 `index.html` 无法加载。
无外部网络依赖 —— three.js 已本地化到 `vendor/`，可完全离线运行。

> 注：测试脚本若在本机代理环境下运行，curl 可能返回 502。
> 加 `--noproxy '*'` 可绕过代理访问 localhost。

### 姿态与动作

- **奔跑时自动俯下身子**冲刺，视高降低、视野收窄；停下则撑起身来（起身比趴下慢）
- **跳跃**：峰值约 0.5m，滞空约 0.5 秒。腾空足够高时可以跳过藏狐扑击
- **第一人称可见自己的爪子与后腿**，会随姿态前伸压低、随攻击挥出

### 屏幕边缘指示

- **红色箭头**：正在逼近的藏狐（首领深红、蓄力时橙色）
- **绿色箭头 + "呼救"**：被困的伙伴，它会周期性叫两声，越远叫得越频繁

## 玩法

每关完成**采食 + 驱退 + 伙伴到家**三目标后回洞，即进入下一关。共 **8 关**。

### 关卡一览

| # | 关卡 | 藏狐构成 | 环境 | 这关要学什么 |
|---|---|---|---|---|
| 1 | 初出洞穴 | 普通狐 ×2 | — | 学会爆发与反击 |
| 2 | 双翼包抄 | 普通狐 / 疾行狐 ×3 | — | 疾行狐蓄力极短，靠拉开距离比靠反应更快 |
| 3 | 持续应战 | +厚皮狐 ×4 | 虚晃×1.3 | 厚皮狐绕到侧面，还会中途虚晃骗你出手 |
| 4 | **雾锁黄昏** | +幼狐 ×4 | 雾 12–68m | 雾很浓，看不见藏狐 —— 盯住地面预警线 |
| 5 | 群狐来袭 | 五种 ×6 | — | 六只围攻，蓄满按 K 清出空间 |
| 6 | **风口疾行** | 疾行狐为主 ×5 | 阵风 7.5 | 横风会推着你走，躲闪要顺着风借力 |
| 7 | **沙尘掩埋** | 五种 ×6 | 沙尘周期 | 沙尘周期性吞掉视野，预警线是唯一依靠 |
| 8 | 首领围攻 | 五种 +首领 ×8 | — | 首领三段连冲，连续躲三次 |

加粗的三关各引入一个**新的物理条件**（能见度 / 横风 / 沙尘），
而不是只把藏狐数量往上加 —— 这是「玩法不单调」的主要来源。

### 藏狐攻击模式

五种藏狐走**完全不同的攻击流程**，目的就是让「看动作猜意图」重新成为玩法核心：

| 类型 | 模式 | 行为 | 冲刺距离 | 反制方式 |
|---|---|---|---|---|
| 幼狐 | **跃扑** | 蓄力后腾空扑击（最高 1.55m） | 10.4m | 跳跃（腾空 >0.34m 免疫），落地 0.9s 硬直可反击 |
| 普通狐 | 直线冲刺 | 蓄力 → 直线冲刺，方向锁死 | 11.5m | 侧移，最基准 |
| 疾行狐 | 疾冲 | 蓄力最短（×0.7）、冲得最远最快 | 12.6m | 提前拉开距离，别硬反应 |
| 厚皮狐 | **绕行虚晃** | 先侧向绕圈，蓄到一半可能**放弃并重新绕** | 12.0m | 看它的实际朝向，别背节奏 |
| 狐首领 | **三段连冲** | 一击三段，每段都能微调方向（追踪） | 8.5m × 3 ≈ 25.6m | 必须连续躲三次，不能一躲了事 |

**关键配平**：藏狐在 `windRange`(9.2m) 处触发蓄力，冲刺距离必须
`≥ windRange − 接触半径`，否则它冲完仍停在玩家碰不到的地方，
玩家站着不动就不会被抓到 —— 预警线也就成了纯装饰。
现在五种类型的冲刺距离都留有 1.5~5m 余量（见 `tools/test-attacks.cjs` 第 4 项）。

### 预警线必须可信

地面预警线是玩家应对突进的**唯一依据**，因此两条守则是硬性的：

1. **方向一致**：线沿藏狐的局部 +Z 延伸，而冲刺方向 `(sin yaw, cos yaw)` 也是 +Z。
2. **长度守恒**：满蓄力时线长**精确等于**真实冲刺距离（`dist × (0.15 + 0.85k)`，k=1 时等于 dist）。

历史上两个 bug 都曾让预警线完全失信：
- 早期用 `ShapeGeometry + rotateX(-π/2)`，绕 X 轴 −90° 把 +Y 映射到 **−Z**，
  于是预警线指向冲刺的**反方向** —— 玩家往线指的另一边躲反而被撞。
- 早期长度系数 `(0.25 + k×0.75×dist)` 满值只到 0.75×dist（8.85m vs 实际 11.47m），
  玩家在最关键的那一刻看到的线是短的。

现在藏狐蓄力/冲刺时，屏幕边缘的威胁箭头会标出它的模式名（如「绕行虚晃」），
玩家从画面外就能读出它接下来要做什么。

### 驱退 ≠ 击杀

**你不会真的杀死藏狐。** 把它们打到体力耗尽后，它们会**夹着尾巴转身逃跑**，
以比玩家更快的速度（8.4 vs 6.6 m/s）奔向草地边缘，逃出视野才消失。
若玩家追上来，它会边跑边改变方向。经过一段时间（关卡的增援间隔），
同类可能再次出现 —— 你只是在保护洞口和采食区，不是在猎杀。
首领被驱退后不会回来。

洞穴是唯一安全区：不能攻击，但能休息回储备、降低应激负荷。

### 远景摆放

`src/models/scene.js` 沿**椭圆环复制 14 份**围成地平线上的树林草甸带：

```
程序化地形边缘 X±215/Z±189  →  摄影测量远景 X±246/Z±218  →  远山 X±330/Z±292  →  雾(far 420)
```

四个必须遵守的约束（都是踩出来的）：

1. **远景必须在地形边缘之外**。放在 172m 会整块埋进程序化地形里，完全看不见。
2. **必须压扁**。源场景是 25m 宽 × **6.8m 厚**的地形块，不是薄片；
   放大 8 倍后是 200m 宽 × 55m 厚的巨块，直接摆出去像一块悬在空中的飞地。
   垂直方向压到 0.55 后才成为贴着地平线的草甸带。
3. **不能跟随玩家位移**。一旦跟随，玩家转身就会看到"贴着的那份消失、背后的露出来"。
4. **远山必须吃雾**。不吃雾时它是不透明实色块，会把更近处的真实草甸挡得看不见。

## GLB 打包的两个坑（自研脚本时必读）

手写 GLB 或改本项目的打包脚本时，注意 three.js 的
`GLTFBinaryExtension` 有两个与规范不完全一致的行为：

1. **`chunkLength` 必须包含 padding。**
   它定位下一个 chunk 用的是 `chunkIndex += chunkLength`，**不会再补对齐**。
   若 JSON chunk 的 length 只写真实内容（靠 padding 单独保持偏移），
   BIN chunk 头部会被读到错位 2 字节处 → `chunkType` 认不出 → `body` 为 null → 整个模型加载失败。
   JSON chunk 用空格 `0x20` 填充（`JSON.parse` 容忍尾随空白）。

2. **`accessor.byteOffset` 是相对所属 `bufferView` 起点的偏移**，不是相对整个 BIN 的绝对偏移。
   `GLTFLoader` 先把 bufferView `slice` 出来，再在这个切片里定位。
   把绝对偏移写进去会越界，报 `Invalid typed array length: <count*itemSize>`。

`tools/test-glb.cjs` 会复刻 three.js 的 chunk 定位逻辑做校验，
能在浏览器外提前抓到这两类错误。

## 关于数值

游戏围绕「神经—体液调节」设计了一套战斗数值抽象：应急爆发（短时资源动员）、
持续动员（较慢的分级调节）、应激负荷过载惩罚、协同大招与疲劳。

**这些数值是玩法设计，不是生理定量结论**，不代表激素一定提高真实动物攻击力，
也不代表应激越高越好。详见游戏内「教师说明」。

`test-attacks.cjs` 覆盖四项硬判据，改动藏狐或关卡表后务必跑一遍：

1. **预警线方向** — 线的世界延伸方向与冲刺方向的点积必须为 1
2. **预警线长度守恒** — 满蓄力时线长 == 真实冲刺距离（误差 < 0.1m）
3. **攻击模式多样性** — 不同类型走不同状态机分支
4. **威胁有效性** — 冲刺距离 ≥ `windRange − 接触半径`（否则预警线形同虚设）
